Area Before After / why it helps
Highlight invalidation Any style mutation in the interface schedules an overlay redraw, including unrelated cube/card/navigation motion. Track highlighted surfaces and occluders. Respond to related ancestors, descendants, scroll, size, and structural changes. Static highlights stop following unrelated motion.
Canvas allocation Both highlight canvas dimensions assigned every redraw. Resize only when backing dimensions change. Pixel density remains capped at 2 as before.
DOM measurements Repeated ancestor measurements, computed styles, and occluder queries for each highlighted surface. Cache these reads within each draw. Refresh the surface registry when structure or marker attributes change.
Navigation geometry Read clientWidth inside every animation update, including after style writes. Measure through ResizeObserver and reuse the width in the animation callback.
Detail card movement Animate top; rewrite the width-dependent blur and CSS variable during rotation. Translate from a stable anchor. Update scale and blur on resize. Same blur strength and card size; subpixel rasterization can differ slightly.
Optical passes Render all four changed face textures, including faces entirely behind the opaque artwork. Skip only when the whole face lies behind z = 0. The final compositor keeps rear tint and edges. A complete 1×1 placeholder keeps unused WebGL samplers valid.
Framebuffer attachment Reattach the same texture on every optical draw. Attach once during initialization; retain stable attachments through storage resizes.
GSAP / WebGL scheduling A GSAP update requests a separate animation frame for WebGL. Queue one draw after GSAP’s timeline updates on its ticker; remove the listener after drawing. Coalesces updates without a permanently active render loop.

Baseline → candidate. One 1.6-second capture window per interaction after loading; Chromium, local production builds. Scene intervals measure CPU draw-call submission spacing, not GPU completion or displayed frames.

In this run, expansion reduced overlay redraws from 13 to 1 (92%), overlay dimension assignments from 26 to 0, and rectangle reads from 287 to 11. Rotation submitted 97 scene draws versus 68 with the same authored duration. Its optical draws increased from 268 to 283 in total because more scene updates were rendered; per submitted scene the ratio fell from 3.94 to 2.92. Framebuffer reattachments fell to zero after initialization. Both renderers issued zero draws while idle.

The general RAF p95 during rotation worsened from 9.1 to 16.8 ms even though scene-submission intervals improved. First-expansion p95 remained about 51 ms. This branch reduces avoidable work and improves observed scene-update cadence in this sample; it does not eliminate all stalls or prove a universal FPS gain. Warm repeated trials and GPU/presentation traces are the next verification step.

Instrumentation counts actual WebGL calls, canvas dimension assignments, and layout/style reads in isolated production pages. It also records requestAnimationFrame intervals, including idle time. Those intervals are not GPU timings or field INP and do not establish an FPS improvement.

Different scene-frame counts are expected when scheduling and available frame budget change. Compare optical work per scene update as well as total calls; a renderer producing more animation frames may issue more total draws while each frame becomes cheaper.

All 20 settled-state checks matched both the glass shader and highlight pixels exactly, including all 12 presets, reduced motion, keyboard selection, resizing, and scrolling. No page or WebGL errors were observed in those checks. The detail-card position differs by at most 0.0142 CSS px due to transform versus layout rounding. Cold mobile startup and intermediate animation pixels were not pixel-validated.

Both isolated builds pass compilation, ESLint, and TypeScript checks with SKIP_ENV_VALIDATION=1, the demo’s documented build mode. Local credentials do not enable Clerk here, so these results exclude authenticated routes and production network conditions. The active workspace’s shared .next directory conflicted with its running development server during an attempted build; final comparisons use independent build directories.

Browser scope: Chromium on this Mac, 1440 × 1000 at DPR 2; additional desktop resize and mobile-placeholder checks. Test on Safari and representative slower GPUs before treating this as a cross-device performance result. No resolution reduction, blur reduction, frame-rate cap, or adaptive quality mode was introduced.

Make ownership obvious.

The main issue is that the shipping interface, authoring workbench, starter backend, and exported deliverables live beside one another without clear boundaries. Keep related code together, retain useful references, and avoid a large reorganization disguised as a performance patch.

Next opportunities, ranked.

1. Share shader programs and static geometry

Four optical passes compile identical shader source and own separate buffers/programs. A shared pipeline with per-face textures/framebuffers could reduce startup work. Profile compilation first, and test context cleanup and all uniform updates before adopting it.

2. Reduce pointer-handler allocation

The magnetic selector repeatedly creates gsap.to() tweens. GSAP recommends quickTo() for repeated updates of the same numeric properties. A follow-up should reuse x/y/scale tweens with the exact existing duration/ease, while testing reset, interruption, touch and reduced-motion behavior. It is not included in this branch.

3. Improve artwork discovery and transfer

The 12,643,893-byte HQ PNG is requested after renderer initialization. Test early preload and a lossless alternative with decoded-pixel/color checks. Keep the source artwork and resolution. Do not exchange optical quality for a smaller download without visual validation.

4. Separate authoring controls from runtime settings

The homepage imports DialKit controller code even when the development panel is hidden. Extract approved settings before attempting a production-only path; persisted tuning values make blindly substituting defaults unsafe.

5. Audit audio and mobile startup

Proximity audio allocates an AudioContext, noise buffer, and oscillators at mount even when muted. Explore lazy initialization on consent/interaction with preserved sound onset. Initial viewport state can briefly initialize desktop graphics on mobile before ResizeObserver runs; gate it using measured availability.

6. Keep shader specialization separate

The shader’s repeated dispersion/frost sampling merits a GPU profile. Channel specialization, shared programs, and WebGL 2 migration change more of the rendering pipeline than this patch. Preserve the existing math until fixed-state pixel checks and GPU timings justify each change.
